# Mandatory historical-failure check for the later BSD research job

This addendum is for the full research task, not the tiny runtime probe. It
adds a priority rule without altering the sealed original package. Apply it
after extraction and before proposing or developing a mathematical mechanism.

1. Search `sources/HISTORICAL_STOPS_AND_CORRECTIONS.md`, all relevant cards in
   `guide/03_WALL_ATLAS.md` (44 cards in the bound version), and the underlying
   dossier and correction records identified there. Paths are relative to
   the extracted `BSD_SEED_ARISTOTLE_2026-10-05/` reading-set root. Use the
   compendium and research map to locate connections, not as substitutes for
   the original argument and its latest correction.
2. Before substantial work, record the closest earlier construction, its
   exact first failed implication, and the source path and section establishing
   that failure. State its scope: an error in one construction, missing input,
   computation limit, and impossibility theorem are different conclusions.
3. A mechanism that leaves that failed implication unchanged is inadmissible.
   Identify the new arithmetic input, theorem, object, hypothesis, or exact
   comparison intended to change it. Renaming a scalar, re-normalizing an
   existing identity, listing more equivalent witnesses, or generating more
   instances is not itself a change to the failed implication.
4. State the precise endpoint consequence before investing in the mechanism:
   uniform/cofinite FIN, finiteness at an explicit exceptional primary
   component, conditional ORDER9, or Q36. A fixed-prime construction must not
   be presented as a uniform argument. Preserve ordinary-only, supersingular,
   and finite-exception restrictions throughout.
5. If no prior match is found, list the search terms and dossier locations
   checked; do not invent a historical obstruction or claim exhaustive novelty.
   If the governing source is missing, identify it and keep the affected
   inference conditional. Do not restart an already screened construction
   merely because its correction has not yet been read.
6. Try the first intrinsic failure test before polishing or expanding the
   construction. A repair is welcome when it changes that failed step. If it
   does not, replace the mechanism rather than completing collateral details.
   Preserve the failed attempt succinctly for future custody.

This is a research-selection rule, not an assertion that the supplied record
contains a BSD proof or that every unexplored mechanism is viable. The full
task still asks for new arithmetic toward the actual seed and allows a
different mechanism with a stated endpoint implication. Do not substitute
formal verification of an implication whose hypothesis is the missing bound
for proving that bound. The tiny runtime probe grants no launch permission.
